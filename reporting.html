Playback reporting & privacy

Small automatic reports help us investigate playback problems that do not quickly go away. You can also choose to share a more detailed record when reporting an issue yourself. Collecting or sending a report does not itself restart playback.

Your choice

Open Settings → Playback diagnostics / Report an issue and uncheck Automatically send minimal persistent-fault reports to stop future automatic reports. This changes the setting only for this browser on this site, not other browsers, devices or player sites. If you have already made a choice, it is kept. Otherwise automatic reporting is on by default. Clearing your browser's saved site data removes that choice.

When automatic reports are sent

A report may be sent if playback stops making progress for about 30 seconds, if the player appears to be playing but receives little or no sound for about 30 seconds, or if repeated attempts to restore playback fail. Brief problems that resolve themselves are not automatically reported. A station may genuinely be silent, so a report does not necessarily mean something went wrong.

The player tries to send at most one automatic report per hour from this browser on this site, even if sending fails. The site also accepts at most three reports per hour from the same internet address, including reports you send yourself. People sharing an internet connection may share that limit. Connection problems or these limits can prevent delivery, so receiving no reports does not prove that playback was trouble-free.

What an automatic report contains

  • Fault type, browser family and major version, app asset versions, and observed HTTP failure status codes.
  • Compact technical state at fault capture and sending: stream/mix mode, pause/mute, connectivity and page visibility, media/context/library state, playback method, rounded remaining buffer, and whether the input appears silent.
  • A stream fingerprint to group affected endpoints, and a temporary random page-session ID to distinguish repeated reports in one page from reports across several page sessions.
  • The server's receipt time. The site is identified in the report email subject.

Automatic reports do not contain nicknames, contact details, full browser user-agent strings, raw stream URLs, track metadata, audio, playback positions or listening/event timelines. Automatic requests omit cookies and referrers. The server accepts only the defined compact fault fields, not arbitrary diagnostic contents.

failure describes playback when the problem was recorded; current describes it when the report was prepared. null means a value was unavailable or not applicable. The fixed elapsed: 3000 is a submission check, not your listening time.

The server adds the time it received the report, and the email subject identifies the player site. These are not extra details collected from your browser.

Fingerprints and session correlation

The stream fingerprint is a SHA-256 hash of the local recorder's bounded upstream origin and path, not the proxy address. Credentials, query strings and fragments are removed first. The same endpoint can therefore be grouped across proxies without sending its address. Query-selected variants may group together, while different aliases for one stream may remain separate. Non-stream sources or an unavailable hashing API produce no stream fingerprint.

A hash is not encryption: someone with candidate stream addresses could match them to fingerprints. Reports are private, but this is not a guarantee that a station cannot be identified.

The session ID is generated randomly, not derived from an IP, nickname or device. It is held only in page memory, never saved in browser storage. It remains the same across reconnections and station changes in that page, but changes on reload or a new page. It links reports within a page session; it does not link browsers or devices. Several sessions do not necessarily mean several people.

IP addresses, storage and access

Automatic fault records and their emails omit IP addresses. The server necessarily sees connection IPs, uses them for rate limiting, and ordinary hosting access logs may retain them. The rate limiter's filenames contain an IP hash. This is data minimisation and temporary session correlation, not guaranteed anonymity.

Submitted reports are stored in a private server log and emailed to the site operator. The report viewer requires authentication; report logs, archives and rate-limit files are denied direct web access. Submitted reports have no built-in expiry. Turning reporting off or clearing local diagnostics does not delete reports already submitted.

Detailed diagnostics and reports you send yourself

The player keeps a short record of playback activity in this tab, whether automatic reporting is on or off. Saved details of problems can remain available for up to 24 hours, including after reloading the page. If the browser cannot save them, the player can still keep a record while the page remains open.

Copy diagnostics copies the detailed record for you to share. Include diagnostics with this report attaches it to a manual issue report only when checked. You can review the record before sharing or use Clear saved data to remove the local evidence.

Detailed diagnostics include timestamps, browser and asset information, playback/buffer/context/gain state, input level (not audio), and stream/proxy server names and paths. URL credentials, query strings and fragments are removed; local-file and blob URLs are reduced to their scheme. Audio, track metadata and raw console messages are not saved. Server paths can still identify private streams, so review before sharing.

Manual issue reports retain the usual nickname, browser user-agent and connection IP, plus your message, optional contact details and any explicitly attached diagnostics. They use the same private log/email destination and have no built-in expiry.

Separate usage logging

The player's existing nickname-based usage logging is separate. This automatic fault-reporting setting does not change that logging or make the whole site anonymous.
